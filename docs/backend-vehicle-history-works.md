# Backend: полная история работ и пробег по авто

Фронт на `/repairs/{id}` и на 3-м шаге создания показывает блок **«История по этому авто»**:

- полный список **выполненных работ**;
- **пробег**, который был указан на каждом этапе (заказ-наряде).

Сейчас часто видно одну строку / без пробега — обычно потому что API не отдаёт `work_items` и/или
`mileage` в истории.

---

## Нужно в ответах

### `GET /api/v1/vehicles/{id}` → `repairs[]`

```json
{
  "id": "12",
  "order_number": "Р-1051",
  "status": "completed",
  "updated_at": "2026-08-12T14:56:24Z",
  "total": 0,
  "mileage": 87200,
  "work_items": [
    { "title": "Диагностика", "is_done": true },
    { "title": "Замена масла", "is_done": true },
    { "title": "Замена фильтров", "is_done": true }
  ]
}
```

### `GET /api/v1/vehicles/search` → `previous_repairs[]`

Тот же контракт:

| Поле           | Требование                                      |
| -------------- | ----------------------------------------------- |
| `work_items[]` | **Все** работы заказа (не одна `title`)         |
| `mileage`      | Пробег **этого** заказ-наряда (на момент работ) |
| `title`        | Опциональный fallback                           |

### Public

`previous_repairs[].work_items` + `previous_repairs[].mileage` — snapshot после `completed`.

---

## Правила

1. `mileage` на истории = значение с **repair_orders.mileage**, не «текущий» пробег авто.
2. После `completed` список `work_items` **не теряется** (snapshot / связь не чистить).
3. Search и `GET /vehicles/{id}` согласованы по полям.

---

## Acceptance

- [ ] В карточке авто каждый прошлый ремонт отдаёт полный `work_items[]`
- [ ] У каждого элемента истории есть `mileage` (если был указан на заказе)
- [ ] После `completed` работы и пробег не пропадают
- [ ] Search и show vehicle согласованы

---

## Коротко бэкендеру

> В `GET /vehicles/{id}` и search в историю ремонтов отдавай полный `work_items[]` и `mileage`
> каждого заказ-наряда. Без этого фронт не может показать полный список работ и пробег по визитам.

# MAX-бот: не подтверждается номер (прод, 23.08.2026)

Отдать Laravel. Фронт не участвует: диалог только MAX ↔ webhook.

Базовый URL: `/api/v1`. Webhook: `POST /api/max/webhook`. Бот: `https://max.ru/id650202270142_bot`
(`id650202270142_bot`). Дока MAX: https://dev.max.ru/docs-api (раздел про кнопку `request_contact`).

---

## Что сломано

`/start` и кнопка «Отправить номер» на проде **уже работают** (это не
`docs/backend-max-start-handoff.md`).

Клиент жмёт **кнопку бота** (не скрепку, не текст `+7…`) → бот отвечает:

> Не удалось подтвердить номер телефона. Попробуйте ещё раз.

Это падение проверки `hash` контакта. Это **не** «клиента нет в базе» — тогда текст:

> Номер не найден в базе СТО. Обратитесь в сервис.

`GET /api/v1/repairs/{id}/notifications` после этого остаётся пустым — подписка не создаётся.

Тестовый номер из карточки клиента (тот же, что у Р-1008): `+7 995 006-08-27`. В аккаунте MAX должен
быть **этот** номер: кнопка шлёт телефон аккаунта MAX, не произвольный из книжки.

---

## Как должно работать

```
кнопка request_contact
  → message_created
  → attachments[].type = contact
  → attachments[].payload.vcf_info
  → attachments[].payload.hash

проверка (дока MAX):
  HMAC-SHA256(MAX_BOT_TOKEN, vcf_info) === hash

hash ок
  → телефон из vcf_info (TEL), нормализовать к 11 цифрам как clients.phone
  → найти клиента → подписки channel=max на все его vehicle_id
  → «Уведомления подключены для: …»

hash нет (скрепка / пересланный контакт)
  → «Нажмите кнопку “Отправить номер”, не делитесь контактом из книжки.»

номер не в базе
  → «Номер не найден в базе СТО. Обратитесь в сервис.»
```

Не принимать привязку по тексту номера без `hash`.

---

## Как считать hash

Поле в webhook: `attachments[].payload`, не `attachments.hash`.

`vcf_info` выглядит так (пример из доки MAX):

```
BEGIN:VCARD\r\nVERSION:3.0\r\nPRODID:ez-vcard 0.10.3\r\nTEL;TYPE=cell:79990000000\r\nFN:Ivan Ivanov\r\nEND:VCARD\r\n
```

Перед HMAC литералы `\r\n` (два символа `\` `r` `\` `n`) заменить на настоящий CRLF. После
`json_decode` в PHP переносы часто **уже** настоящие — второй раз «разэкранировать» не нужно. Не
сводить CRLF к одному `\n`. Не хешить сырой JSON с экранированными `\r\n`.

PHP:

```php
hash_equals(
    hash_hmac('sha256', $vcfInfo, $botToken),
    $hash
);
```

Ключ — актуальный `MAX_BOT_TOKEN` из `.env` (тот же, которым бот шлёт сообщения). После смены
токена: `php artisan config:clear && php artisan config:cache`. Токен не писать в git, логи и ответы
API.

## Что проверить на сервере

На одно нажатие кнопки в лог webhook (без токена):

| Поле                | Если нет / false                                 |
| ------------------- | ------------------------------------------------ |
| `type=contact`      | событие не то или другой хендлер                 |
| есть `payload.hash` | клиент не той кнопкой; не та же ошибка, что HMAC |
| `hash_ok`           | неверный токен или нормализация `vcf_info`       |
| клиент найден       | нормализация телефона ≠ `clients.phone`          |

Частые причины `hash_ok=false`:

- в `.env` старый/другой токен, `config:cache` со старым значением;
- хеш не `hash_hmac('sha256', vcf, token)`;
- смотрят не `payload.hash`;
- ломают переносы в `vcf_info`.

## Проверка, что починили

1. `/start` → кнопка → «Отправить номер» → «Уведомления подключены для: …».
2. `GET /api/v1/repairs/{id}/notifications` → `channel=max`, `is_active=true`, есть `chat_id`.
3. `PATCH /repairs/{id}/status` `in_progress` → `done` → сообщение в MAX.
4. Скрепка / чужой контакт → не подписка, отдельный текст, не «не удалось подтвердить» как у кнопки.
5. Номера нет в базе → «Номер не найден в базе СТО…».
